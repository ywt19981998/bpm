# DOCX 结构化字段恢复设计

## 目标

选题申报表始终以 DOCX 上传。系统先直接解析 Word 表格，稳定识别选题名称和第一作者姓名；只有关键字段仍为空时，才调用一次 DeepSeek Flash 做结构化补全。模型结果必须能在脱敏后的原文中找到直接证据，否则拒绝写入。

## 已确认问题

- 合并表格行可能以“章节标题、字段名、字段值”三个单元格出现，旧逻辑按固定奇偶位置配对，会把字段值丢掉。
- `姓 名`、`选题名`等带空格或简写的标签未映射到统一字段名。
- BPM 标题和作者只读取少量别名，没有消费已经生成的作者正文作为结构化数据源。
- 非敏感抽取结果仍携带原始表格行，若直接发给模型可能包含证件号、电话和地址。

## 处理链路

1. 用 `python-docx` 读取段落和表格，不做 OCR。
2. 对字段标签去除空白与括号提示，并映射为规范字段名。
3. 同时执行“相邻已知标签扫描”和旧的成对扫描，兼容章节标题开头及普通多列行。
4. 在 `include_sensitive=False` 时，同时脱敏字段字典和原始表格行。
5. 检查 `选题名称`、`姓名`两个核心字段；均存在时不调用兜底模型。
6. 字段缺失时，仅把脱敏表格行、段落和缺失字段列表发送给 DeepSeek Flash，并要求严格 JSON。
7. 只接受在脱敏原文中原样出现的候选值；不允许模型推测或改写姓名、书名。
8. 把通过校验的值合并回 `canonical_fields`，再进入报告 Pro 模型和 BPM 数据构建流程。

## 隐私与失败策略

- 证件号、电话、邮箱、邮编和通信地址在非敏感抽取中统一替换为 `[已隐藏]`。
- 兜底模型调用失败、返回非法 JSON 或给出无原文证据的值时，只记录缺失字段名，不记录字段值，不阻断后续报告生成。
- 快速导入已有申报表和策划报告时使用同一字段恢复逻辑，但不重新生成报告全文。

## 验收标准

- `姓 名 | 朱万浩`规范为 `姓名=朱万浩`。
- `选题情况 | 选题名 | 数智赋能：西门子S7-1200 PLC项目式教程`能读取完整选题名。
- 原生解析完整时 Flash 调用次数为 0。
- 原生解析缺失时 Flash 最多调用 1 次，且仅合并原文可验证的值。
- 非敏感 payload 的表格行不泄露联系方式或证件信息。
- 报告生成和“申报表 + 已确认策划报告”快速导入都使用恢复后的标题与作者。
