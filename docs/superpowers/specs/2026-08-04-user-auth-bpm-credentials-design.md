# 用户登录与 BPM 凭据持久化设计

## 目标

在现有内网网站中加入轻量级用户体系。任何能够访问内网网址的人都可以注册，注册只收集账号、密码和姓名。每个用户可以配置并持久化自己的 BPM 账号密码，之后执行 BPM 任务时自动使用当前登录用户的配置。DeepSeek 模型由服务端统一配置，前端不再要求用户选择模型或填写 API Key。

## 范围

本次包含：

- 用户注册、登录、退出和会话恢复。
- SQLite 本地数据库。
- 用户姓名作为报告署名和 BPM 策划编辑、拟责任编辑的默认来源。
- BPM 账号密码的加密保存、更新、清除和自动调用。
- DeepSeek 服务端统一配置及前端模型设置移除。
- 用户维度的持久任务记录。

本次不包含：

- 手机号、邮箱、单位、部门等额外注册信息。
- 手机短信、微信、企业微信或第三方 OAuth 登录。
- 用户角色、付费、配额、找回密码和管理员后台。
- 将网站开放到公网所需的域名、备案和 HTTPS 部署。

## 用户流程

### 注册与登录

1. 未登录用户只能看到登录和注册界面。
2. 注册时填写账号、密码、确认密码和姓名。
3. 账号全局唯一；姓名允许重复。
4. 注册成功后自动登录并进入工作台。
5. 用户可随时退出；会话过期后重新登录。

### BPM 配置

1. 用户首次进入 BPM 工作区时看到“尚未配置 BPM 账号”。
2. 用户填写 BPM 账号和密码并保存。
3. 后续页面只显示 BPM 账号和遮蔽后的密码状态，不回传密码明文。
4. 用户可修改或清除配置。
5. 发起作译者维护或选题填报时，后端读取当前用户的 BPM 配置，解密后仅在该任务进程内使用。
6. 未配置 BPM 凭据时，BPM 按钮不可提交，并给出明确提示。

### 报告与署名

- 当前登录用户的姓名作为报告文件名中的编辑姓名。
- BPM 的策划编辑和拟责任编辑默认使用当前用户姓名及其现有身份映射。
- Playwright 打开 BPM 表单后，优先读取当前登录账号自动带出的策划编辑、拟责任编辑及隐藏编号；若姓名与网站登录用户姓名一致则原样保留。
- 若 BPM 表单没有自动带出当前用户，使用 BPM 人员选择器按网站用户姓名选择并让 BPM 自己回填编号；匹配不到则在暂存前停止，不能静默套用其他人的编号。

## 页面设计

### 登录页

- 登录和注册使用同一页面的两个页签。
- 登录字段：账号、密码。
- 注册字段：账号、姓名、密码、确认密码。
- 不展示产品营销内容，登录后直接进入现有工作台。

### 顶部用户区域

- 显示当前用户姓名。
- 提供“BPM 配置”和“退出登录”入口。
- 不在全局导航中显示任何密码或 API Key。

### BPM 配置面板

- BPM 地址固定为系统配置，不允许普通用户修改。
- 字段仅包含 BPM 账号和 BPM 密码。
- 已保存状态显示账号和“密码已保存”。
- 保存、更新和清除使用明确按钮；清除操作需要确认。

### 模型设置

- 删除现有模型 URL、模型名称和 API Key 输入区。
- 前端只显示生成进度和错误，不暴露服务端模型配置。

## 数据设计

SQLite 数据库默认位于 `data/app.db`，数据库文件不提交 Git。

### users

- `id`：整数主键。
- `username`：唯一账号，规范化后比较。
- `password_hash`：使用适合密码存储的哈希，不保存明文或可逆密文。
- `display_name`：用户姓名。
- `status`：`active` 或 `disabled`，用于停用账号而不删除历史数据。
- `created_at`、`updated_at`、`last_login_at`。

### sessions

- `id_hash`：会话令牌哈希。
- `user_id`：关联用户。
- `created_at`、`expires_at`、`last_seen_at`。

浏览器仅保存随机会话令牌 Cookie，Cookie 设置 `HttpOnly`、`SameSite=Lax`。内网 HTTP 阶段不启用 `Secure`；未来部署 HTTPS 时必须启用。

### integration_credentials

- `id`：整数主键。
- `user_id`：关联用户。
- `system_type`：外部系统类型，BPM 使用 `phei_bpm`。
- `ciphertext`：将账号和密码组成 JSON 后整体加密得到的密文。
- `nonce`：AES-GCM 随机参数。
- `key_version`：加密密钥版本。
- `config_json`：不含敏感信息的扩展配置。
- `created_at`、`updated_at`。

`user_id` 与 `system_type` 组成唯一约束。以后新增合同系统、OA 或其他平台时复用该表，不再增加新的密码表。

BPM 凭据使用 AES-GCM 等带认证的加密方式。每次保存生成新的随机 nonce，账号和密码作为同一个 JSON 载荷一次性加密，避免在同一密钥下重复使用 nonce。加密主密钥由 `APP_CREDENTIAL_KEY` 环境变量提供，不写入数据库、源代码或 Git。密钥缺失时服务拒绝保存和解密 BPM 凭据。

### jobs

- `id`、`user_id`、`job_type`、`title`、`status`。
- `input_path`、`output_path`、`error_summary`。
- `created_at`、`started_at`、`finished_at`。
- `status` 使用 `queued`、`running`、`succeeded` 或 `failed`。
- 可保存选题名称、任务编号和脱敏错误摘要，并为每个用户提供自己的任务历史。
- 禁止保存网站密码、BPM密码、会话令牌、API Key和完整请求头。

### schema_migrations

- `version`：唯一迁移版本号。
- `applied_at`：迁移完成时间。

服务启动时按版本顺序执行缺失迁移，不通过删除数据库来升级结构。

## 服务端认证边界

- 所有生成、导出、BPM和任务日志接口都必须先验证网站会话。
- 客户端提交的用户 ID、姓名和 BPM 凭据不作为可信身份来源。
- 后端根据会话取得用户 ID和姓名，根据用户 ID读取 BPM 凭据。
- BPM 密码只在任务工作线程和 Playwright 子进程环境中短暂存在，任务结束后移除引用。
- API 响应和任务持久化数据不得包含 BPM 密码。

## DeepSeek 配置与模型路由

服务端统一使用：

- Base URL：`https://api.deepseek.com`
- 主模型：`deepseek-v4-pro`
- 快速模型：`deepseek-v4-flash`
- API Key：`DEEPSEEK_API_KEY` 环境变量

真实 API Key 不写入源代码、HTML、SQLite或 Git。部署者只需配置一次，所有网站用户共享使用。

第一阶段路由保持简单：

- “生成全部”及一到六部分润色统一使用 `deepseek-v4-pro`。
- 作者姓名确定性解析失败后的补充识别可使用 `deepseek-v4-flash`。
- 简短结构化修复、三级和四级分类补充可使用 `deepseek-v4-flash`。
- DOCX解析、固定成本文本、DOCX导出和 Playwright BPM填写不调用模型。

为控制改动范围，第一阶段可以先将现有单次完整生成调用切换为 Pro；Flash 兜底仅在相应独立调用存在或新增时启用，不把完整报告拆成多个模型请求。

## API 设计

- `POST /api/auth/register`：注册并创建会话。
- `POST /api/auth/login`：登录并创建会话。
- `POST /api/auth/logout`：删除当前会话。
- `GET /api/auth/me`：返回当前用户 ID、账号和姓名。
- `GET /api/integrations/phei-bpm`：仅返回是否已配置和脱敏账号状态。
- `PUT /api/integrations/phei-bpm`：保存或更新加密凭据。
- `DELETE /api/integrations/phei-bpm`：清除凭据。

现有业务接口继续保留，但由后端会话注入姓名和 BPM 凭据，不再接收前端传来的 BPM 密码、模型 URL、模型名或 API Key。

## 错误处理

- 注册账号重复：返回明确的字段错误。
- 登录失败：统一提示账号或密码错误，避免泄露账号是否存在。
- 会话过期：返回 401，前端回到登录页并保留未上传文件之外的安全草稿状态。
- BPM凭据解密失败：提示重新保存配置，不输出底层密文或密钥错误。
- DeepSeek未配置：管理员可从服务日志看到配置缺失，用户只看到服务暂不可用。
- BPM认证失败：任务标记失败，提示用户更新自己的BPM配置。

## 兼容与迁移

- 数据库启动时自动创建缺失表，并使用轻量 schema 版本号管理后续升级。
- 现有页面本地保存的模型配置停止使用并在初始化时清除。
- 现有未登录访问在功能上线后统一跳转登录页。
- 当前服务器上的 API Key 迁移到环境变量；上线前更换已经在聊天或历史配置中暴露过的密钥。

## 测试与验收

### 自动测试

- 注册、重复账号、登录失败、退出和会话过期。
- 密码数据库中仅存在哈希，不出现明文。
- 通用外部系统凭据加密往返、错误密钥、更新和清除。
- BPM凭据接口永不返回密码。
- 未登录用户不能调用生成、导出、BPM或任务日志接口。
- 不同用户只能读取自己的BPM配置和持久任务。
- DeepSeek请求固定使用服务端模型配置，忽略客户端伪造字段。
- 现有报告生成、DOCX导出、作译者维护和选题填报测试继续通过。

### 手工验收

1. 注册两个用户并分别登录。
2. 两个用户保存不同BPM账号密码，重新登录后配置仍有效。
3. 两个用户分别发起BPM任务，确认使用各自账号且日志不泄露密码。
4. 前端不再出现模型设置，生成报告默认使用V4 Pro。
5. 数据库和任务输出中搜索测试密码、API Key，结果必须为空。
